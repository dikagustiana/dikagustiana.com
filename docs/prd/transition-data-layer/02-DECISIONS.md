# Decisions taken while building

Where the build departs from `01-PRD.md`, or settles something it left open, it is listed here
with the reason. Nothing below changes a "keputusan yang masih kamu pegang"; those are in
`04-STATUS.md` with the default the build uses until Dika decides.

| # | Decision | Why |
|---|---|---|
| D1 | The tracker stays at **`/green-transition/tracker`**; a chart's page is **`/green-transition/tracker/chart/:slug`**. `/transition/tracker` and `/transition/tracker/:slug` redirect there. | Every Green Transition page lives under its section, the old tracker URL is already indexed and linked, and `/green-transition/tracker/:issueSlug` is taken by the old issue redirects. "Redirect halaman Tracker lama" is satisfied because the old page *is* the new page. |
| D2 | **No Recharts.** Charts are drawn in SVG by `src/components/transition/TransitionChart.tsx` (≈450 lines with the timeline). | Recharts was removed from the site for weight (GATE_LEDGER row 5, REVIEW-2026-08 R09). The PRD's own performance target (under 2 s on 4G) and the essay pages' weight work argue against bringing a ~100 KB chart library back. The chart has what the PRD asks of it: tooltip, keyboard reading, table view, CSV, projections dashed, policy markers. Essays load it lazily, only when they embed a chart. |
| D3 | **Nine tables, not eight:** `ds_chain` holds the author's status line for each link. Enum `chart_type` adds **`timeline`** (the policy link's chart, which draws register entries, not values). Observations carry a **`member`** (the energy source in a mix). | The design asks for a status slot "ditulis penulis, bukan dihitung mesin", which needs a home; the policy link has no numeric series in the MVP; `ember.idn.generation` is one series with one line per source. |
| D4 | Generation is stored as **TWh** (`ember.idn.generation`), not % share. Coal's share has its own series. | The inventory row says TWh; a stacked TWh bar shows the mix and the growth together. |
| D5 | The **sector register stays on the tracker page**, below the charts, and the chain section appears only once a chart is published. | Every chart lands unpublished with a bracketed title, so replacing the register would have emptied the public page until Dika writes the findings. The register also feeds the markers. |
| D6 | **Seven public views** (`v_series_latest`, `v_chart_data`, plus `v_chart_catalog`, `v_series_status`, `v_series_history`, `v_chain`, `v_chart_usage`) and `v_macro_editions`. anon still has no privilege on any `ds_` table. | The detail page needs the vintage picker, revision history, check badge and "esai pemakai"; each is a narrow view with its own column list, the `essay_structure` pattern (definer views, `security_barrier`). |
| D7 | Rules: **R0** (something is staged) added; **R7** holds the publish until an admin ticks it, and the fetcher can never confirm it (`ds_run_publish_gate` has no confirm parameter); **R8** is a warning that never holds. Every run writes a `GATE` row with the outcome. R7's threshold is per series (`ds_series.r7_threshold`, default 0.25). | A job must not wave through a large revision; a gap in the source (BI rate 2001–2005) is information, not a reason to stop. The per-series column answers the open "ambang R7" question without changing the default. |
| D8 | A value equal to the latest published value of its period is **not inserted again**. | A weekly pull would otherwise add every row every week; "revisi menambah baris" is kept, because a changed value is a new row under its new vintage. |
| D9 | The service role is **revoked** from writing `ds_observation`, `ds_check`, the registry and the charts. It may read, stage, clear its own staged rows, and log runs. | PRD, Risiko: "Key hanya bisa menulis staging, publish tetap lewat aturan." Tested: the service role's INSERT on `ds_observation` is refused (`supabase/tests/transition_data_layer.sql`). |
| D10 | WEO is in the **weekly IMF run**. A new edition is picked up the week it appears; the workflow can also be run by hand for one series. | An unchanged edition adds nothing (D8), so the weekly run costs nothing; a manual-only trigger is a step someone forgets. |
| D11 | Fase 4's `v_macro_assumptions` is a **function**, `ds_macro_assumptions(edition)`, with `v_macro_editions` listing the editions. FX and coal are calendar-year averages **as published by the edition's month**, with `n_months` shown. | A view cannot take the edition as a parameter; a function that raises on an unpublished edition cannot silently fall back to another. No projection of FX or coal is made (PRD, Bukan tujuan). |
| D12 | UI copy is **English**, like the rest of the site and the register. `ds_series.title_id` is stored for a later bilingual page. | Default until Dika decides the bilingual question. |
| D13 | A mix draws at most **eight members** (Nuclear is left out of the Indonesian mix). | The categorical palette validates eight colours in order (adjacent CVD ΔE ≥ 9.1); a ninth would need a generated hue. |
| D14 | `src/integrations/supabase/types.ts` is **not** edited; the new tables and views are read with casts, as `useTrackerEntries` does. | The file is generated from the live schema; regenerate it after the migrations are applied. |
| D15 | `chartEmbed` stores **only the slug**; the essay shows the chart's live values. An unpublished or unknown chart renders nothing for a reader and a named placeholder in the editor. | PRD, Hubungan dengan tabel yang ada. The sanitizer gains one attribute, `data-chart-slug`, validated against the slug pattern on every read. |
